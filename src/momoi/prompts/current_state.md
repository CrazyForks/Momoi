# 更新眼下需要记住的状态

当前状态是带有效期（TTL，最多 24 小时）的短期记忆，保存的是现在忘了就容易说错话或做错事的临时事实。
有些临时事实覆盖了长期默认情况；有些出现得太近、持续得太短，不能指望最近七天的记忆或按需召回来得及提供。

根据上面的聊天记录，判断 `pending_turns` 带来了哪些当前状态变化。证据冲突时，以最新一轮为准。

通常的流程：… → memory_operation(scope=memory)? → current_state_finish

以本次提供的状态快照为准，只提交尚未反映在快照中的变化。没有新证据，不重复写入或延长有效期。

## 什么值得加入

加入前问自己：“在这件事实际有效的时间里，忘了它会不会让我说错或做错？”。通常涉及：与已知日常、尝试、习惯相违背。
如果不会，就不加，无论它多值得记住。

例如：
- 今天是打车去公司，而非日常的骑车通勤。-> 加入，并且 TTL = 10hrs，覆盖上班~下班的完整时间。
- 热量计算：今天总共吃了 1000 大卡，晚饭还没吃。 -> 加入，并且 TTL = 8hrs，覆盖到晚餐。
- 睡 2 个小时午觉。 -> 加入，并且 TTL = 2hrs，覆盖到午觉完成。
- 刚喝了水。 -> 不加入，忘记不会犯错，也不是持续状态。
- 上个厕所。 -> 不加入，琐碎日常。
- 今天骑车通勤。 -> 不加入，非记忆冲突的日常默认行为。

使用状态前，先看来源时间、说话者和不确定性。原文直接说明的内容才能记为 `observed`；推断使用 `inferred`，并说明不确定之处。按工具说明提供来源轮次和原文引用，运行时会核实说话者和时间，不自行编造证据。

**区分长期记忆和临时状态**。

某条规则、偏好、关系、方法或跨事件状态，在眼前这件事过去后仍值得知道，就通过 `memory_operation` 记录。这里只放在实际适用时段内可能改变、或时段结束后可以忘记的短期状态和行为。例如：

- 我没有水杯，都是用一次性的杯子。 -> 不加入，跨事件、并且以后可以持续，更适合放到 recall 记忆中。
- 早上没吃饭。 -> 加入，并且 TTL = 10hrs，覆盖到晚餐事件。
- 我早上不吃饭。 -> 不加入，这是习惯性、通常性的行为，更适合放到 recall 记忆中。
- 我今天 140 斤了。 -> 不加入，短期（TTL）内体重无法改变。

## 整理已有状态

每个 slot 只写一条简洁的、提炼出的当前事实，不夹带来源、叙事或背景。例如，把“早上八点他说今天打车了”整理成“今天的通勤方式：打车”。

每次都检查并整理所有 slot。已经结束、互相冲突、重复，或不再符合加入条件的内容，都删掉。事实和历史混在一起时，用一条清楚的当前事实替换，不保留混杂的版本。具体替换方式按工具 schema 执行。

## 按实际持续时间设置 TTL

TTL 表示事实还会适用多久，不表示它有多重要。明确限时的行为要求也属于临时状态，不因已有相近长期偏好而忽略其适用时段。对方给了时长或日期，就据此计算；只说“今天”而没有更具体范围的，按照此事件的常识时间结束。

根据事实的实际过程确定时间，不习惯性地填 24、12 或 8 小时。午睡可能几分钟后结束，工作安排到约定时间结束；不知道何时结束，就不要猜测持续时间。两个时段都说得通时，选有依据的较短一个。无法确定有效期或是否仍然适用，就不添加。新证据表明已经结束时，提前删除。

## 重要准则

- 慎重添加，不要什么不重要的细节都塞到里面。
- 提炼事实和状态，只保留必要细节。
- TTL 选定要慎重，不要习惯性填长时间，按照生活常识判断时常。
- 拿不准时默认不加；没有实质变化就不修改。
