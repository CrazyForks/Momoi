# 选择本次检索需要的记忆

从 Episode、已确认记忆和反思记忆的候选中筛选内容，只通过 `select_topics` 返回三组索引，按对当前请求的帮助程度排序；不写解释或评分。

## 筛选步骤

1. **确定需求**：以当前请求为准。检索查询只是搜索线索，不增加新需求。具体事件要对上人物、对象、动作和可区分的情境；宽泛话题可以跨多个事件。只共享实体或关键词不算同一事件。
2. **逐条核对**：Episode 看标题、摘要和执行证据；已确认记忆看 kind、key、content；反思记忆还可看日期、置信度和 evidence。候选必须与需求直接相关，或明确提供同一事项的有用前因、后续。问具体决定或安排时，周边活动不足以证明答案；只按候选明确写出的内容判断，不补造事实。
3. **处理版本**：问当前状态或有效安排时，只有候选内容明确表明同一事项被更正、取消或替代，才舍弃失效且无额外用途的旧候选。问历史或变化过程时，保留所需的前后记录。无法确认是否同一事项或是否发生替代时，不推断新旧关系。
4. **处理反思冲突**：反思记忆仅作辅助，不能单独证明事实，也不能覆盖相冲突的已确认记忆。同一事项的反思记忆彼此冲突时，按 `local_date` 保留日期最新的一条，舍弃较旧的冲突内容；同日或日期不明时保留相关候选供后续核实。不同方面的反思可以并存。
5. **去重并输出**：重复表述只保留最清楚、完整的候选；额外的相关细节仍可保留。逐条判断后排序，不按输入顺序凑数；没有相关候选就返回空列表。

cue 只是检索线索，不能证明事件发生；摘要或 cue 缺失不代表无关。`conversation_time` 只表示 Episode 关联聊天的时间，不能单凭它认定事件发生时间或事实版本。反思的 `local_date` 只用于上述反思之间的冲突取舍，不证明事件发生日期。
